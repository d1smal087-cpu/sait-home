# Возврат к F2 из версии 0.1.7

Это отдельный запуск точных файлов старого ZIP 0.1.7 — той версии, после которой пользователь подтвердил выбор цели через F2. Текущие исходники, config.json и .venv не заменяются. Новый файл test_f2_017.bat только запускает старый test_controls.py через уже установленный .venv/Scripts/python.exe. Папка старого кода — rollback-0.1.7.

1. Закрой работающие тесты. Распакуй содержимое этого ZIP в текущую папку LU4 Observer, рядом с .venv. В этой папке должны появиться test_f2_017.bat и папка rollback-0.1.7.
2. В самой игре верни на F2 действие «следующая цель». Spoil на F2 для этой проверки не нужен. Встань рядом с видимыми мобами, закрой ввод чата и сними выделение через Esc.
3. Запусти test_f2_017.bat от имени администратора. За 10 секунд вернись в LU4, отпусти модификаторы и оставайся в игре около 15 секунд. Observer запускать не требуется.
4. Проверь версию 0.1.7, режим scan, hold 300 ms и elevated True в консоли. Тест отправит одну F2. Пришли журнал из rollback-0.1.7/runs и результат: появилась ли выбранная цель.

Тест использует старую конфигурацию из своего config.example.json. Калибровка OCR для него не нужна. Клавиша F2 и её действие в игре — единственный предмет этой проверки. Автоатака, Spoil и текстовые команды не отправляются. F9 отменяет ожидание.

Старый код не изменён: проверено побайтовое совпадение всех его файлов с исходным опубликованным ZIP, CRC обоих архивов, Python-компиляция и 50 тестов старой версии. Реальный ввод на Windows здесь не проверяется. Прежний успех выбора цели не гарантирует запуска навыков.

Последнее уточнение пользователя по 0.3.1: программа набрала /useskill Spoil, строка после Enter исчезла, но навык не применился. Следовательно, пользователь наблюдал реакцию на Enter; объяснять отказ навыка только несработавшим Enter оснований нет. Причина различия ручного и программного запуска остаётся неизвестной.

Если старый тест снова выберет цель, фиксируем его как воспроизводимую исходную точку. Если результата не будет, откат сам по себе проблему не решает; дальнейший выбор способа ввода требует новой диагностики. Смена Python на другой язык сама по себе не меняет поведение используемого Win32 SendInput.
